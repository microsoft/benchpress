# Temporal Deployment Stress Test

## Paper mapping

Section 5.3 (Predicting Newly Released Models) in the main body. Previously this experiment lived appendix-only; it was promoted to §5.3 because it answers the third operational question of Section 5 (deployment against a brand-new release).

## Purpose

Test the deployment setting where a new model appears after the current training matrix. The target set is selected by a pre-specified metadata-and-coverage rule before looking at prediction errors: release date on or after DeepSeek R1 (`2025-01-20`), release date no later than GPT-5.1 (`2025-11-13`), and more than 20 observed benchmark scores in the final matrix. For each selected target model, the predictor may use only models released before that target's cutoff date; `k` of the target model's observed benchmark scores are revealed, and BenchPress predicts the remaining observed scores for that model. The shard records all observed scores of the active target model: revealed cells are exact zero-error predictions, hidden cells with finite BenchPress predictions enter MedAPE/MedAE, and hidden cells on benchmarks that have no finite deployment prediction are marked `not_predictable`.

The paper-facing metrics are MedAPE and MedAE, computed with `benchpress.evaluation_harness.compute_prediction_error`.

## Parallel execution

The independent unit is `(target, k, seed)`: 27 hard-rule targets x 3 k values x 10 seeds = 810 shards. `run.py --mode run-all --workers N` runs or reuses those shards in parallel. CPU thread counts should be pinned by `run.sh`; full runs should use a remote CPU machine.

## Inputs

- Canonical score matrix from `benchpress/build_benchmark_matrix`
- Model release dates from the canonical model records
- Current BenchPress default predictor: Logit Bias ALS, rank 2, lambda 0.1

## Outputs

- `results/shards/*.json.gz`: one shard per `(target, k, seed)`, including the target/training model IDs, revealed benchmark IDs, per-cell raw rows for all observed target cells, and shard metrics. Raw rows include `is_revealed`, `is_metric_cell`, and `prediction_source`; revealed cells have `pred=actual`, while non-predictable hidden cells have `pred=null`. Hidden rows also carry `model_mean_pred`, the logit-space model mean fit on the same training matrix, as a same-cell baseline.
- `results.json`: merged canonical payload with config, hard-rule target definitions, raw predictions, and paper-facing summaries.
- `results.json` also includes `summary_hidden_only_by_k` and
  `summary_hidden_only_by_family`: hidden-cell-only pooled MedAE/MedAPE,
  coverage, and per-target hidden-only MedAE inputs.
- `table.tex`: LaTeX table generated by `gen_table.py`.
- `hidden_only_summary_by_k.json`: optional hidden-only table helper generated
  by `gen_table.py --hidden-summary-json hidden_only_summary_by_k.json`.
- `figures/bp_temporal_deployment_boxplot.{pdf,png}`: main-body box/strip plot generated by `plot.py`.

## Resume / rerun

Existing shards are reused only if their config matches the requested `(target, k, seed)` and protocol version. Stale or incompatible shards are overwritten during `run-all`, while `--mode merge` refuses to merge incompatible or missing shards.

Training-cell date audit (May JSON and loader): the final 84 x 133 matrix has 2,604 observed cells, and all 84 final model rows have model release dates. No final observed cell has a non-audit source/report/publication/retrieval date in the primary score record or in its `candidates`; only 14 / 2,604 cells (0.54%) have `audited_at`, which records an audit timestamp rather than the score report date. The raw May JSON likewise has no non-audit score-date field (72 / 4,905 raw score rows have `audited_at`). Therefore this artifact supports release-clean training by model row, but not training-cell masking by score report date without adding external source-date metadata.
